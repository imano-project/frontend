# 0001. 決めたことを ADR で記録する

- 状態: 採用
- 日付: 2026-10-20

## 背景
AI エージェントを使って開発すると、理由があって選んだやり方を、AI が「より良い書き方」だと判断して変えてしまうことがある。
また、あとから参加した人には、なぜその構成になっているのかが分からない。

## 決定
方針を決めたときは、`docs/decisions/` に1件1ファイルで、決めたことと理由を記録する。

## 理由
- 理由が残っていれば、AI も人も、変える前にそれを読める
- 1件1ファイルにすると、いつ何を決めたかを追いやすい

## 影響
- 方針を変えるときは、新しいファイルを書き、古いファイルの状態を「置き換え」にする
- 設計のルール（[ARCHITECTURE.md](../ARCHITECTURE.md)）を変えるときは、先にここへ記録する
